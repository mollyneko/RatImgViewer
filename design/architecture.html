0产品定位与性能目标

定位：轻量看图器，不是编辑器。只做三件事 —— 打开快、翻页快、少见的格式也能看。所有决策围绕下面这几个数展开。

✅ 做（Keep）
浏览与缩放 · 缩略图网格 · 旋转翻转 · 非破坏性裁剪 · 亮度/对比度/饱和度 · 幻灯片 · 放大镜 · 复制 / 设为壁纸 / 打印 · 格式转换与批量另存 · CDR 等矢量查看 · EXIF 与直方图
🚫 不做（Non-goals）
图层编辑与 PSD 分层导出 · AI 抠图 / 去水印 / 超分（要拖几十 MB 模型）· 长图拼接与拼图 · 透视校正 · 曲线 / 色阶 / 降噪等专业调色 · 标注与水印 · 画布尺寸调整。这些交给外部工具，UI 里直接不出现。

1总体分层架构

UI 层只做显示，所有像素操作都在原生层完成，Electron 不参与逐像素计算。

2CDR 是怎么被画出来的（核心难点）

CorelDRAW 私有二进制格式从未公开。业界唯一可行路径是逆向后的 libcdr + librevenge 链路（LibreOffice 同宗），而不是像大多数看图器那样「偷偷调用 CorelDRAW.exe 另存」——后者既慢又依赖盗版。已落地（V1.0.0）：libcdr 编译为独立转换进程 vendor/cdr2svg/cdr2svg.exe（librevenge 生成 SVG，Chromium 原生渲染）。选独立进程而不是 N-API 进程内加载：恶意/损坏 CDR 崩溃时不会连累看图器本体；产物按「路径+mtime+页码」缓存，文件没变不重转。打开时内嵌预览先秒显，矢量后台转换完成后热替换；没有内嵌预览的文件直接走矢量通道（实测 LibreOffice 官方语料 84/84 全通过，单文件毫秒级）。

版本兼容矩阵
CDR 1~2024CDT 模板 CMXCDRX v16+ 加密 CDR（提示无法解析）
渲染难点
CMYK→RGB 需用其内嵌 ICC 做相对色度转换，否则品牌红会偏；渐变网格(mesh)与艺术笔触(artistic media)支持不全，需回落为近似描边。
输出能力
对象树保留 → 可直接导出 SVG / PDF 矢量，而非只有位图；印刷场景提供「按 mm + DPI」精确输出。

  return core.toShared(bmp);                   // 不序列化
});

4工程目录结构

Electron + Vite + React 渲染层；原生层为独立 CMake 工程，产出 .node Addon。

⚠️ M1 实现现状（有意偏离设计）
渲染层没有用 Vite + React，改为 原生 HTML/CSS/JS（src/renderer/ 三个文件）。 理由：本产品定位是「轻量 + 启动快」，去掉打包器与运行时后安装包更小、冷启动更快，也更契合 「看图软件就该秒开」的心智。原生内核（C++ Addon）因本机没有 C++ 工具链暂缓， 本版 CDR/PSD/RAW 先用内嵌预览提取兜底（见第 2 节兜底链路）。
实际目录：src/main/（main · preload · scanner · exif · preview · cache · assoc）+ src/renderer/（index.html · styles.css · app.js）+ build/（图标 · NSIS 钩子）。

6保留的操作与实现方式

轻量路线的取舍标准只有一条：这个操作是不是「看」的一部分。是 → 做；不是 → 交给外部工具，UI 里直接不出现。 所有操作默认非破坏性，原文件永不被就地改写。

类别操作实现方式矢量
浏览查看 缩放（滚轮 / 适应窗口 / 适应宽度 / 1:1）、平移、翻页、幻灯片、全屏 视口变换矩阵 + 瓦片按需重采样，UI 线程零解码✅
辅助查看 放大镜 2× 取景、像素网格、EXIF、直方图、主色板、动画播放控制 放大镜走 shader 采样；动图按文件内逐帧时长播放（不假定固定 fps）✅
几何变换 顺时针 / 逆时针旋转 90°、任意角度、水平 / 垂直翻转 只写 EXIF Orientation + sidecar 角度，导出时才应用✅ 改对象变换矩阵
裁剪 自由 / 固定比例 / 自动切白边 非破坏性裁剪矩形，可随时撤回完整画面✅ 输出框裁剪
轻量调整 亮度 · 对比度 · 饱和度 · 一键美化（仅此四项） 预览走 GPU shader；导出时在原生位深上一次性计算，避免反复量化丢阶⚠ 光栅化后
文件操作 重命名 F2 · 删除 · 移动 / 复制 · 复制图片到剪贴板 · 复制路径 · 设为壁纸 · 打印 · 用外部编辑器打开 删除走 shell.trashItem 进系统回收站，绝不 unlink；剪贴板同时写 CF_DIB 以兼容 Office✅
输出 另存为（默认另存副本）· 格式转换 · 限制长边 · 批量另存 JPG / PNG / WebP / AVIF / TIFF，保留 ICC 与 EXIF；矢量源可导出 SVG / PDF 保矢量✅
安全阀 撤销 / 重做 · 未保存提醒 操作栈只存参数，回溯 O(1)；关闭窗口时若有未导出修改需二次确认✅
为什么砍掉专业编辑
抠图、拼接、曲线调色这类功能要么要带几十 MB 的模型与依赖，要么要一整套面板和状态机。做进来体积与复杂度翻倍，使用率却只有 5%，还会拖慢启动。
砍掉之后省了什么
省掉 ONNX Runtime、曲线/色阶编辑器、批注图层与序列化、超分模型 —— 主包少 40 MB 以上，首屏少一次模型加载。
用户要做深度处理怎么办
右键「用外部编辑器打开」+ 可配置的编辑器列表，一键跳 Photoshop / 画图 / 你惯用的工具。看图器不该假装自己是 PS。

7开发里程碑（轻量路线）

4 个阶段，每一阶段结束都能独立交付一个「能用」的看图器，不出现半成品功能。

阶段交付物验收标准
M1 骨架Electron 无边框窗口、双主题、四屏布局（看图 / 管理 / 对比 / 批量）冷启动 < 1.5 s；主题切换无闪白；安装包 < 25 MB
M2 看家本领基础位图解码 + 视口缩放平移 + 缩略图网格 + EXIFJPG/PNG/WebP/GIF/BMP/TIFF 全通过；4K 图 < 60 ms；1000 张缩略图 < 2 s
M3 矢量引擎CDR / AI / EPS / PDF / SVG / WMF 解析（差异化卖点）100 份真实 CDR 稿通过率 ≥ 92%，失败者回落内嵌预览图，绝不显示灰块
M4 打磨收尾轻量调整、裁剪浮层、放大镜、批量另存、删除走回收站常驻内存 < 180 MB；免安装便携版可用

8已知风险与应对

⚠ libcdr 对新版 CDR 支持滞后
CorelDRAW 2023/2024 的新记录类型可能解析失败。应对：对象树解析失败即刻回落内嵌预览图，并上报匿名格式样本用于迭代。
⚠ 打包体积
libraw + libheif + libavif + skia 全量约 60 MB。应对：按需拆分 codec 插件 DLL，主包仅带 JPEG/PNG/WebP/SVG。
⚠ Windows 上第三方 RAW 专利解码
部分厂商白平衡数据在 libraw 还原后有偏差。应对：优先读取文件内嵌 JPEG 预览，必要时提供厂商 SDK 可选开关。
⚠ GDI / DXGI 多屏混合 DPI
拖拽到副屏时瓦片重渲染。应对：监听 display-metrics-changed，按目标屏 DPI 重建纹理。

为什么把 JPG/PNG 放在第一优先级
它们占日常看图量 90% 以上。如果连基础位图都要装插件、或首次打开要下载解码器，产品在第一分钟就被卸载。所以 M2 里程碑只交付基础位图，也必须先交付它。
插件失效的兜底顺序
完整解码 → 内嵌预览图（多数专业格式自带）→ 生成低清代理图（首次打开时后台生成）→ 明确告知「暂不支持该版本」并给出替代方案，绝不静默显示灰块。
